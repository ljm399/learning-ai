# 主逻辑
修改/api/chat为agent编排模式的逻辑
1. 准备一个编排主agent，用户的消息首先给到编排主agent，该agent只负责编排调用哪些节点，该agent会输出json表明调用哪些节点，以及每个节点的参数，每个节点都是一个独立的方法
2. 按照主agent下发的json，用代码解析json，依次执行每个节点。
# 节点
1. 请求接口节点
2. 获取服装推荐攻略节点
3. ai选品agent，负责根据攻略和用户需求选定一个具体商品或者商品种类
4. ai筛选商品agent，根据用户的需求和商品列表。筛选出2-3个商品
5. 自定义上下文agent，也就是该agent纯粹是请求大模型接口。由编排agent决定他的上下文

# 细节
1. 每一个节点需要有一个前端提示词，执行到某个节点通知前端显示这个提示词。所以agent在编排时，要安排好提示词。

2. 可以把内部业务接口列举给编排agent。方便在使用请求接口节点知道该请求哪个接口，用什么参数
3. 如果需要一些前面节点的数据可以使用模板语法，执行的之后根据context替换
